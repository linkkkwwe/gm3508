# 2026-09-17 · GUID_RAIL 电机波形诊断

## 背景
用户上传 SerialPlot 截图（2191×847），抱怨"代码写的是正弦，电机转起来波形不对"、"
曲线不平滑"。工程为 STM32F407 + M3508/C620，MDK-ARM，Application/ 下
Motor.c / pid.c / trajectory.c / serialplot.c / CAN_receive.c。

## 结论 1：正弦被角度限位削顶成梯形
- `application/trajectory.c:6` `TRAJECTORY_AMPLITUDE = 60.0f`，注释写的是"±30°"。
- `application/Motor.h:33-34` 限位 `HORIZONTAL_MIN/MAX_ANGLE_DEG = ∓30.0f`。
- `Motor.c` 里 `constrain_float(target_angle, min, max)` 硬截断 → ±60° 正弦被切成
  平顶梯形。像素级复核：平台段占周期的 1/3，与正弦在 ±30° 处截断的理论值一致。
- 另有注释/数值不一致：`TRAJECTORY_PERIOD_MS 4000` 注释写"6 秒"；
  `g_horizontal_max_out` 注释写 5000 实际 16384、`g_horizontal_max_iout` 注释写 0 实际 5000。

## 结论 2：第三路通道（PID 输出）在运动段约 7Hz 全幅振荡
截图按颜色分离出三路：青 (0,174,126) / 紫 (126,45,210) / 品红 (255,0,86)。
- 紫、品红 = 两路角度（目标 / 实际），逐列只有 2~4 px 起伏，平滑，两条几乎重合。
- 青色 = `g_dbg_pid_output`（第三路），逐列最多 99 px。
- 青色平台段起点 x = 0/333/859/1287/1795，平坦长度 106/259/218/275/253 px；
  爆发段 x 区间与角度斜坡段**逐段对齐**，即：**只在运动时振荡，静止时完全恒定**。
- 爆发段内每 17~18 px 反向一次 → 周期约 35 px。角度梯形周期约 945 px = 4000 ms
  → 1 px ≈ 4.2 ms → 振荡周期 ≈ 145 ms → **≈7 Hz**。

## 控制链参数（复核过）
- 控制环 1 ms：TIM6 PSC=83 / ARR=999，定时器时钟 84MHz → 1ms ✓
- SerialPlot 10 ms 发一次，三通道共用一根 Y 轴（角度 ×10 满量程 ±600，电流 ±16384）
  → 量级差 27 倍，角度被压平、电流显得"炸屏"
- PID：Kp=500 / Ki=0 / Kd=200，D 项为裸一阶差分、无滤波、无 dt 归一化
- `HAL_UART_Transmit` 在 115200 下阻塞约 1.3ms，每 10 个周期一次，会让个别控制周
  期变成 2ms，D 项增益随之波动

## 分析方法（可复用）
纯 Node（无第三方库）解 PNG：IHDR/IDAT → zlib.inflateSync → 逐行反滤波
（None/Sub/Up/Average/Paeth）→ 按精确 RGB 分类像素 → 逐列取 min/max 还原各通道轨迹。
对线图尤其有效：可直接量出振荡周期、平台段长度、各通道偏移。

## 结论 3（15:51 第二张截图，1210×814）：抖动 = 位置环"几乎无阻尼"的自激振铃

用户把 `Motor.h` 限位放宽到 **±60°**（15:33 改，注释仍写着 ±30°），所以正弦不再被削顶——
第二张图里目标角已经是干净正弦，反向验证了结论 1。

- 仍是三路：青 = PID 输出，紫/品红 = 目标角 / 实际角（平均差 0.6 px，最大 16 px → 跟随很好）。
- 青色**全程**振荡：极值法周期 42 px，自相关法 44 px。参考角自相关周期 971 px = 4000 ms
  → **4.12 ms/px** → 振荡周期 ≈ 181 ms → **5.5 Hz，等幅不衰减**。
- 参考角停在顶点/谷底（x≈890..935）时青色峰峰仅 ~100 px，一离开极值就涨到 300~770 px，
  换向处最大；包络对比：静止段 247 px vs 运动段 413 px（比值 0.60）。
  → 换向是激励源，但振铃不衰减是环路本身无阻尼，不是纯机械爬行。
- 该图三路**不是共用一根 Y 轴**（角度原始量程只有电流的 1/27，却各占满画面高度），
  所以这张图只能读形状、不能读幅值——判断幅值必须改 serialplot 的发送比例或加独立轴。

### 根因（可量化）：D 项缺 dt 归一化 → 阻尼比 ζ ≈ 0.007
- `pid.c:52` 的 `Dbuf[0] = error[0] - error[1]` 是"每 1 ms 的误差变化量"，**没有除以 dt**。
- 等效连续微分增益 = Kd × T = 200 × 0.001 = **0.2（电流单位 / (°/s)）**，而不是 200。
- ζ = Kd_eff·ωn / (2·Kp) = 0.2 × 34.6 / (2 × 500) ≈ **0.007**，Q ≈ 72。
- 振铃衰减时间常数 1/(ζ·ωn) ≈ **4.2 s** ≈ 一个轨迹周期 → 图上看不到衰减。
- 要把 ζ 提到 ~0.6，Kd 需 ≈ 2ζKp/(ωn·T) ≈ **17000~20000**（当前值的 ~100 倍）。
- 更干净的做法：用 `speed_rpm` 做速度阻尼（现在 `Motor.c:130` 用 `(void)speed_rpm;` 丢掉了），
  换算关系 输出角速度(°/s) = speed_rpm × 6 / 19.2032 = **0.3125 × speed_rpm**。
- 风险：Kd 放大 100 倍后，编码器 1 计数（0.00229° 输出角）会带来约 40 单位的电流噪声，
  且丢一帧 CAN 会让该次差分归零 → 建议加一阶低通，或直接改用 speed_rpm。

### 待确认
限位放宽到 ±60° 后**没有软限位保护了**：如果机构实际行程只有 ±30°，这是撞机的隐患。
正确组合是"限位保持 ±30° 不动 + 把 `TRAJECTORY_AMPLITUDE` 改成 30"。

## 结论 4（16:02 第三张截图，1401×1131）：**真正的"不平滑"是低频爬行，不是高频抖动**

这张是 SerialPlot 放大视图，只有两路（目标角 / 实际角），青色 PID 输出跑出视图外。
代码未改动（main.c 仍是 15:43、Motor.h 仍是 15:33 那版）。

### 标定（自洽性验证过）
- 品红峰顶 x=135 / 1114，峰间距 979 px = 4000 ms → **4.086 ms/px**
- 品红峰峰 1037.5 px = 120°（±60°）→ **8.646 px/°，即 1 显示单位(0.1°) = 0.865 px**
- **两路共轴**（不是独立缩放）的判据：紫峰顶比品红低 8 px、谷底对称地高 8 px，
  峰峰值小 16 px（1.5% 幅值衰减）。独立自动缩放下两路的峰顶应精确重合 —— 8 px 的差只可能
  来自共轴下的真实幅值差。所以这张图的幅值可以直接读。

### 实测：实际角在极值附近"完全静止"，不是"缓慢"
紫色（实际角）出现 7 段逐像素水平的平台（容差 1 px）：

| 相位 | x 范围 | 时长 | 平台 y | 期间目标角走了 |
|---|---|---|---|---|
| 峰顶① | 124–179 + 180–202 | 223+91 = **314 ms** | 39.0→40.5 | **4.9°** |
| 下降沿① | 238–252 | 60 ms | 144.0 | 3.8° |
| 谷底① | 609–685 | **306 ms** | 1059.5 | 4.1° |
| 峰顶② | 1094–1181 | 247+103 = **350 ms** | 38.5→40.5 | 5.2° |
| 下降沿② | 1216–1231 | 64 ms | **144.0** | 3.8° |

- 卡滞总占比 **19.6%**（275/1401 列，全程 5.6 s 里有 1.1 s 完全没动）。
- **两个周期卡在完全相同的 y=144.0、相同长度** → 确定性极限环，不是随机摩擦噪声。
- 卡滞时长 ∝ 1/目标速度：极值处（目标速度≈0）卡 300~350 ms，斜坡中段只卡 60 ms。
- 脱困时速度：x=203–218（61 ms）紫从 42 冲到 100.5 = 58 px = **6.7°**，平均 **110°/s**，
  同期目标只有约 40°/s → **2.7 倍**猛冲。
- 非卡滞段：紫稳定滞后品红 5–15 px（0.6–1.7°），是正常相位滞后（约 24 ms，对应带宽 ~6.6 Hz）。

### 根因：Ki = 0 的纯 PD 环 + 静摩擦 = 爬行极限环
1. 目标速度降低（接近极值）→ 误差 e 变小 → 输出 → 0；
2. **`g_horizontal_ki = 0`，唯一能"顶住静摩擦"的机制不存在** → 输出掉进摩擦/电调死区 → 电机停住；
3. 误差重新积累，但只有 Kp×e 在撑，要涨到 2~5° 才够挣脱；
4. 挣脱时 ζ≈0.007（见结论 3，Kd 缺 dt 归一化）没有任何阻尼 → 以 2.7 倍目标速度冲过头。
5. 冲平后误差再次归零 → 回到第 1 步。周期 300~400 ms。

这也解释了"为什么极值处卡最久"——那里目标速度最低，误差积累最慢。
调 Kp/Kd **治不了**这个，必须先有积分项 + 减小机械摩擦。

1. `g_horizontal_ki`: 0 → 100 左右（在线 Debug 改，不用重编译）
2. `g_horizontal_kd`: 200 → 20000（补偿缺的 dt 归一化，ζ→0.6）
3. `g_horizontal_max_out`: 16384 → 4000
4. 代码改法（更正确）：D 项补 dt 归一化 + 用 speed_rpm 做速度阻尼 + 积分抗饱和
5. 机械侧：导轨润滑 / 预紧 / 回差、联轴器刚度。300 ms 级卡滞说明摩擦不小。

## 结论 5（用户问"拐角附近波动比较大"）：拐角 = 换向点，是爬行最严重的地方

用户自行改了 `Motor.c`（16:07）：**Kp 500→300、Kd 200→1700**，Ki 仍为 0。

### 由前几张实测图反推出的对象常数（这次能定量预测了）
- Kp=500 时实测 5.5 Hz 等幅振铃 → ωn=34.6 rad/s → **Kt/J = ωn²/Kp = 2.39 (°/s²)/指令单位**
  （即：每 1 个电流指令单位产生 2.39 °/s² 的角加速度，含减速比折算后的输出轴）
- 脱困指令：上一张实测，Kp=500 时轴停住期间目标已走过 4.9° 才脱困 →
  **U_break ≈ 500×4.9 ≈ 2450 指令单位（≈16% 量程）**，这就是静摩擦的等效值。
- 当前 Kp=300 → ωn=26.8 rad/s(4.26 Hz)，Kd_eff=1.7 → **ζ=0.076、Q=6.6、振铃 τ=493 ms**

### 关键结论：**降 Kp 会让拐角更糟**
Ki=0 时脱困力矩只有 Kp·e 一条来源，于是：
- 脱困所需误差 = U_break / Kp → Kp 500: 4.9°、**Kp 300: 8.2°**、Kp 800: 3.1°
- 停滞时长 ≈ sqrt(e / (A·ω²/2)) → Kp 500: 257 ms、**Kp 300: 332 ms**（实测当时 310~350 ms ✓）
→ 用户把 Kp 从 500 降到 300，等于把拐角死区宽度放大了 1.7 倍。**方向反了。**

### 含摩擦模型的时域仿真（1 ms 步长，静/动摩擦 1:0.62）
 reproduces 实测形态：接近顶点前 68 ms 就抱死 → 停 449 ms（停在 57.4°，没到达 60° 顶点）
 → 目标已走开 8.4° 才脱困 → 以 **140°/s** 追赶（目标峰值速度才 94°/s，1.5 倍）
 → 越过目标后回弹 8.2°，靠 ζ=0.076 慢慢衰减。
所以"拐角处波动大"= 每半周期一次"粘住→攒够误差→弹射→回弹"，**不是跟踪带宽不够**。

### 建议
- 不要降 Kp；要么保持 500，要么（更好）用前馈替代 errors 产生力矩。
- **摩擦/速度前馈**最对症：轨迹是解析正弦，ω_ref、α_ref 闭式可得，
  u_ff = J/Kt·α_ref + sign(ω_ref)·Fc，Fc≈2400 指令单位。前馈后 Kp 可以保持很低也不产生死区。
- Kd 需 ~13500 才到 ζ=0.6（1700 只到 0.076）；但继续堆 Kd 会放大量化噪声，
  先给 D 项加一阶低通或改用 speed_rpm 做阻尼。
- Ki 仍是 0，这是爬行的根因（注意 `pid.c:47` 是 `Iout += Ki*e`，没乘周期 →
  数值比常规小 1000 倍，取 1~3 量级即可，别按教科书填）。

# 2026-10-17 工作记录

## 需求：手动档去限位 + 零点改成手动停下的位置

用户原话：「现在手动的不加限位然后零点位置改成手动停下的位置」。
语义确认：手动档推到哪算哪（软件不拦），摇杆回中停下的那一刻，
把停下的物理位置设为新的 0° 参考；之后继续手动从 0 起算，
切波形也以这个位置为中心摆动（HOMING 会走回这个新 0°）。

### 改动（3 个文件，共 6 处）

**Motor.h**
- 新增 `extern volatile uint8_t g_horizontal_rezero_req;`
  置 1 → update() 下一帧把当前编码器位置记为新 0° 参考。
- 新增 `extern volatile uint8_t g_horizontal_limit_off;`
  1 = 跳过目标角度的 ±720° 夹紧。

**Motor.c**
- 定义上面两个变量（默认 0U）。
- `motor_ctrl_update()` 在 initialized 分支之后新增 rezero 块：
  `offset_ecd = ecd; last_ecd = ecd; total_rounds = 0; current_angle = 0;
   Pid_clear(); return 0;`（重设帧不输出电流）。
- 目标限幅改成 `if (!g_horizontal_limit_off) target = constrain_float(...)`。

**rail_control.c**
- 删掉 `RAIL_LIMIT_DEG`、`RAIL_SLOWDOWN_FRAC` 两个宏（手动档不再有减速带/硬夹紧）。
- 新增 `#define RAIL_STICK_DEADZONE 30`：|stick| ≤ 30 判为"回中停下"。
- 新增 `static uint8_t zero_set;`（init 里清零），防止每帧重复重设。
- `manual_step()`：去掉减速带与夹紧；回中且 `!zero_set` 时置
  `g_horizontal_rezero_req = 1U` 并把 `manual_target` 归零，然后 `zero_set = 1U`；
  离开死区时 `zero_set = 0U`（下次停下再设一次）。
- `rail_control_update()` switch 之前：`g_horizontal_limit_off = (mode == RAIL_MANUAL) ? 1 : 0`。

### 关键设计点（下次别改错）
- **重设零点必须和 manual_target 归零同一帧做**。只重设零点而目标留旧值，
  误差会突然变成"旧目标"那么大，电机会猛冲回去。
- 重设只平移坐标系（offset_ecd = 当前 ecd），物理位置不动，所以不跳变。
  副作用是停下瞬间的跟随误差被抹掉——这正是"零点=停下的位置"的语义。
- `manual_step` 的返回值就是这一帧的 target，所以 main.c 里
  `motor_ctrl_update(..., rail_control_update(...), ...)` 的实参求值顺序保证
  rezero_req 一定在同帧被设置并消费（rail_control_update 是 motor_ctrl_update 的实参）。
- 死区内（|stick| ≤ 30）仍会按实际 stick 累加 step，只是不再重设零点。
  ADC 中位噪声不会导致反复重设（zero_set 已置 1），但电机会缓慢漂移。
  想让回中彻底不动就把死区内的 step 也强制归零。

### ⚠️ 风险（已告知用户）
手动档软件限位完全失效：Motor.c 的 ±720° 夹紧在手动档被关掉，
撞到机械端点不会自己停。波形/归位/SAFE 仍保留 ±720° 夹紧。
另外波形模式仍是 ±720°/2000ms（峰值 2260°/s），用户尚未处理。

## 三角波换向打滑（咨询，未改代码）
- 用户现象：三角波档换方向时皮带会滑一下。
- 根因是**轨迹数学属性**，不是 PID：三角波顶点是速度阶跃（C0 连续、C1 不连续）。
  当前参数 A=720°/T=3000ms → 匀速段 V=4A/T=960°/s，拐点 Δv=1920°/s 要在 1ms 内完成
  → 需求加速度 1.92e6 °/s² → 按 Kt/J=2.39 需电流 ~80 万，撞满 16384 硬冲约 49ms。
- 推论：**降 Kp/Kd 治不了**（只会加大滞后）；**降速也治不了**（T 加到 6s 需求仍有 40 万，
  照样撞满）——三角波在数学上加速度就是无穷，除以 2 还是无穷。必须改形状。
- 方案与峰值电流需求：圆角抛物线 tb=150ms → 4200；tb=300ms → 2850；正弦 720°/3s → 2800
  （加速度 A·(2π/T)²=3158°/s²）。注意正弦峰值速度 1508°/s 反比三角 960 高 57%，
  若打滑主因是速度而非加速度，正弦会更糟。
- 圆角实现式（顶点 τ∈[-tb,tb]，τ=t-t_顶点，V=4A/T）：
  x(τ)=A+V·τ−(V/(2tb))·(τ+tb)²，峰值被削 V·tb/2，可用内幅 A+V·tb/2 补偿。
- 另一条路：Motor.c 输出加 **slew rate 限幅**（每帧电流变化上限），等价效果且对正弦/手动都有效，
  还能做成 Watch 变量实时调。

### 已实施（用户确认：同步带 + 选方案 A）
- **用户确认是同步带** → 所谓"打滑"实为**跳齿**。
- 改动只落在 `Application/trajectory.c` 两处（未动 PID / Motor.c）：
  1. 新增 `#define TRAJECTORY_CORNER_MS 200.0f`（顶点倒角半宽，总换向时间 2×=400ms）。
  2. `triangle_angle()` 头部加两段抛物线接管：+A 峰用
     `A + v·t1 − 0.5·accel·(t1+tb)²`，−A 谷用取反形式，`accel = v/tb`，v=4A/T。
     抛物线两端位置与速度均与直线段精确连续（手算验证：τ=∓tb 处两侧均为 ∓489.6°、速度 ±1152°/s）。
- 用户把 `TRAJECTORY_PERIOD_MS` 从 3000 改成 **2500**（V 从 960 升到 1152°/s），
  所以按 A=720/T=2.5s 配的：tb=200ms → 加速度 5760°/s²、电流约 2400、峰值削 115°（±605°）。
- 保住 ±720 行程的方法写在宏注释里：AMPLITUDE→835 且 Motor.h 限位放宽到 ±835，否则被夹紧削掉。
- **重要隐患（已告知用户）**：闭环反馈在电机轴编码器上，跳齿造成的滑块位移误差**不会被检测到**，
  会累积。判断是否累积：跑一阵后手动归位，看是否回不到原点。

### 编译错误：htim6 undefined（已修）
- 现象：`Core/Src/stm32f4xx_it.c(266)` 报 `#20: identifier "htim6" is undefined`。
- 原因：`TIM6_DAC_IRQHandler()` 是手写在 `/* USER CODE BEGIN 1 */` 区的，但文件头没 include `tim.h`，
  而 `htim6` 的 extern 声明在 `Core/Inc/tim.h:35`。CubeMX 不会自动补这个 include。
- 修法：在 `stm32f4xx_it.c` 的 `/* USER CODE BEGIN Includes */` 里加 `#include "tim.h"`。
  ⚠️ 必须放 USER CODE 区内，否则 CubeMX 重新生成会被冲掉。
- 顺带确认链路完整：`MX_TIM6_Init()`(main.c:105)、`HAL_TIM_Base_Start_IT(&htim6)`(128)、
  `HAL_TIM_PeriodElapsedCallback`(233) 都在，1ms 控制节拍没问题。
- 剩余 2 个无害 warning：`main.c:58` `plot_divider` 未使用（SerialPlot 输出段被注释导致）、

### 起步跳齿：波形从 0° 启动是速度阶跃（已修）
- 现象（用户确认的场景）：**HOMING 归位结束后起波形的一瞬间**皮带跳齿。
- 根因：波形都从相位 0（0°）起步，而 **0° 恰是速度最大的位置**：
  三角起步就要 1200°/s，正弦起步就要 1885°/s（A·2π/T，峰值速度，比三角还大）。
  从 HOMING 的 200°/s 切过去 Δv = 1000 / 1685 °/s → 需求加速度 1.0e6 / 1.69e6 °/s²
  → 撞满 16384 硬冲 25 / 43 ms。与三角顶点是同一类问题（速度不连续），只是位置不同。
- 修法：**起步渐入（时间重参数化）**，只改 `trajectory.c` 两处，正弦/三角原逻辑零改动：
  1. 新增宏 `TRAJECTORY_START_RAMP_MS 300.0f` + 函数 `ramp_elapsed(uint32_t)`：
     t<ta:  τ = 0.5t − (ta/2π)·sin(πt/ta)   （dτ/dt 从 0 升到 1）
     t≥ta:  τ = t − ta/2                     （斜率恒 1，仅相位落后 ta/2）
  2. `calc_angle()` 里 `uint32_t traj_ms = ramp_elapsed(elapsed_ms);`，正弦/三角都用它算相位。
- Node 仿真验证（A=900/T=3s/ta=0.3/tb=0.2）：
  起步区首帧速度 **0.0**（原来是 1200/1885 阶跃）；峰值加速度 6283(三角)/9800(正弦)
  → 电流 2629/4101。稳态区峰值加速度 6000(三角圆角)/3948(正弦)→ 电流 2510/1652。
  全程峰值电流 ≈4100，离 16384 限幅很远。
- 代价：轨迹相位整体落后 ta/2 = 150ms，周期性轨迹无影响。
- 遗留小阶跃：HOMING 走到终点时自身速度 200°/s → 0，Δv=200 撞限幅但只持续 ~5ms，未处理。
